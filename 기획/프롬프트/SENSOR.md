## 최신 확정 설계

센서 데이터 경로는 **Arduino → USB 시리얼 → 브라우저 Web Serial API**다. 서버를 거치지 않는다.

접촉식 마스크 얼라이너의 실제 순서인 **평행 → 회전·위치**를 교육 흐름에 사용한다.

```text
모형 기울기 roll/pitch → 수평(평행) 맞추기: 0°에 가까워져야 함
모형 비틀기 yaw       → 화면 웨이퍼 회전 θ: yaw가 주 센서 입력
X/Y 위치              → 키보드 방향키
```

예전의 `roll→X`, `pitch→Y` 조이스틱 매핑은 폐기됐다. 그 방식으로 문서나 펌웨어를 고치지 마.

센서를 붙인 웨이퍼 모형은 **실제 장비의 조작기를 대신하는 교육용 컨트롤러**다.
실제 공정에서 웨이퍼를 손으로 기울여 정렬한다는 뜻이 아니다.
센서가 없어도 키보드로 전체 실습은 가능하며 센서는 가점 요소다.

## 바꾸면 안 되는 최종 출력 규격

```text
WME,<t_ms>,<roll>,<pitch>,<yaw>\n
```

- `t_ms`: 보드가 켜진 뒤 경과 밀리초, 정수
- roll/pitch/yaw: 도(°), 소수점 둘째 자리
- 한 줄에 샘플 하나, `WME,` 접두사 필수
- 115200 baud, 20ms 주기, 초당 50회
- roll/pitch는 MPU6050 가속도와 `atan2`로 보드에서 계산
- yaw는 자이로 Z축 적분. 시간이 지나면 밀리는 것이 정상이며 그 정도를 이번에 측정
- 외부 센서 라이브러리 없이 `Wire.h`만 사용하고 레지스터를 직접 읽는다
- 디버그용 `DBG`나 원시값 출력은 확인이 끝나면 반드시 제거한다

## 실제 부품과 연결

| 항목 | 실제 확인 상태 |
|---|---|
| 보드 | Arduino UNO / ATmega328P, 5V 로직 |
| 센서 | MPU-6050 계열 모듈, I2C 주소 `0x68`, WHO_AM_I `0x68` 확인 |
| 배선 | UNO `5V→VCC`, `GND→GND`, `A4→SDA`, `A5→SCL` |
| 핀헤더 | 사용자가 2026-09-13 납땜 완료 |
| USB | 데이터 통신과 업로드 확인 |
| IDE | Arduino IDE 2.3.5에서 업로드 성공 |

이전 컴퓨터에서는 `/dev/cu.usbmodem101`과 `/dev/cu.usbmodem1101`이 모두 사용된 적이 있다.
**새 컴퓨터에서는 포트 이름이 달라질 수 있으므로 하드코딩하지 말고 실제 Arduino UNO 포트를 먼저 찾는다.**
IDE에서 보드는 `Arduino Uno`, 포트는 실제 연결된 UNO를 선택한다.

## 지금까지 실제로 확인한 것

### 연결과 전송

- Arduino UNO 업로드 성공
- MPU6050 주소 `0x68`, 식별값 `0x68`을 3초 간격으로 여러 번 연속 확인
- 최종 WME 펌웨어에서 실제 샘플 169개, 평균 50.0Hz, 간격 19~21ms 수신, 오류 없음
- 후속 복구 확인에서도 WME 121개, `DBG` 0개, 오류 없음

### pitch 60° 조사

과거 짧은 수신에서 `WME,3067,-2.70,60.00,0.00`이 나왔지만 당시 원시 가속도는 기록하지 않았다.
그 뒤 센서를 책상에 평평하게 놓고 원시 가속도와 각도를 함께 읽었다.

- 진단 샘플: 268개, 보드 시간 3067~8408ms(5.341초), 평균 49.991Hz, 오류 없음
- 평균: `ax=-0.00414g`, `ay=-0.06893g`, `az=1.02572g`
- 평균 각도: `roll=-3.84463°`, `pitch=0.23060°`
- pitch 범위: `0.03~0.47°`
- 출력 원시값으로 별도 재계산한 pitch와 보드 출력의 최대 차이: `0.00717°`
- 저장된 펌웨어에는 pitch를 60°로 제한하는 코드가 없음

따라서 **평평한 현재 자세에서 pitch 60° 고정·계산식 오류는 재현되지 않았고 계산식은 원시값과 일치했다.**
과거 60° 당시 원시값이 없으므로 실제로 기울어 있었는지는 확정할 수 없다.
roll 약 -3.84°는 ay 치우침과 일치하지만 실제 잔여 기울기와 센서 영점 오차를 아직 분리하지 않았다.
임의로 영점을 빼거나 계산식을 바꾸지 마.

### 현재 보드 상태 — 반드시 주의

사용자가 실시간 값을 천천히 보기 원해, 보드에는 현재 **1초에 한 번 출력하는 임시 1Hz WME 펌웨어**가 올라가 있다.
마지막 화면에서 WME 시각이 1000ms씩 증가하는 것을 확인했다. 움직이는 동안의 예시는 다음과 같다.

```text
WME,10068,-6.61,-13.74,7.85
WME,11068,-4.95,-13.10,-2.32
WME,12068,2.78,-9.97,5.33
```

이 값은 사용자가 움직이는 동안 본 화면 예시일 뿐 공식 측정 결과가 아니다.
**저장소의 `hardware/firmware/wme_sensor/wme_sensor.ino`는 최종 50Hz 코드 그대로다.**
공식 측정 전에 이 저장소 스케치를 다시 컴파일·업로드하고, 50Hz와 WME 5필드 형식을 확인해야 한다.

## 다음 컴퓨터에서 실행할 순서

### 0. 새 컴퓨터와 포트 준비

1. 저장소 최신 상태를 받고 위 문서를 모두 읽는다.
2. Arduino IDE와 Arduino AVR Boards가 준비됐는지 확인한다.
3. 사용자가 센서와 USB를 연결했다고 말하면 Arduino UNO의 실제 포트를 찾는다.
4. 시리얼 포트는 한 프로그램만 열 수 있다. 업로드·터미널 수집 전에 IDE 시리얼 모니터와 브라우저 Web Serial을 닫는다.
5. 저장소의 최종 `wme_sensor.ino`를 Arduino Uno에 업로드해 임시 1Hz 펌웨어를 50Hz로 교체한다.
6. 115200 baud에서 `INFO,KEEP_STILL_CALIBRATING` → `INFO,READY` → `WME,...`를 확인한다.
7. 정상 WME 샘플의 평균이 약 50Hz이고 필드가 정확히 5개인지 확인한다.

### 1. 할 일 0 마무리 — 자세 변화 연속성 확인

공식 측정 전에 임시 진단 출력으로 `ax,ay,az,roll,pitch,yaw`를 함께 본다.

1. 센서 기판만 평평하게 놓고 5~10초 읽는다.
2. 내가 한 번에 하나씩 안내하며 사용자가 앞/뒤/왼쪽/오른쪽으로 천천히 기울인다.
3. 원시 중력축과 roll/pitch가 각 자세에서 연속적으로 변하는지 확인한다.
4. 여러 자세에서 계속 정확히 60.00이면 포화 원인을 찾고, 원시값은 정상인데 각도만 틀리면 계산식을 고친다.
5. 오류가 재현되지 않으면 기존 계산식을 유지한다. 과거 값을 억지로 설명하지 않는다.
6. 진단이 끝나면 `DBG`와 원시값을 제거하고 최종 WME 50Hz 코드로 복구한다.
7. 복구 후 WME 정상 출력과 `DBG` 0개를 실제로 확인한다.

### 2. 측정 도구를 최신 요구사항으로 수정·검증

현재 `data/capture_drift.py`, `data/analyze_drift.py`, `data/README.md`는 **이전 1분·1° 자동 판정 방식**이다.
실측 전에 다음처럼 고친다.

- 수집: 첫 정상 샘플 후 안정화 30초, 이어서 보드 시간으로 180초 기록
- 분석: roll 최대−최소, pitch 최대−최소, 시작 대비 yaw 60초 변화, 시작 대비 yaw 180초 변화
- 품질 확인: 기록 시간, 샘플 수, 평균 Hz, 최대 샘플 간격, 시각 증가와 형식 오류
- 출력에서 `screen_buttons`, `within_drift_limit`, 1° 자동 판정과 채택 결론을 제거
- 숫자만 보고하고 HEADER가 판단하게 한다
- 기존 실측 파일 덮어쓰기 금지와 부분 기록 거부 유지
- 합성 자료는 `/private/tmp`에서만 검증하고 `data/raw/`에 넣지 않는다
- 변경 후 Arduino에 업로드하지 않아도 가능한 Python 검증을 수행한다

기본 저장 파일은 기존 HEADER 지시를 따라 `data/raw/drift_2026-09-13.csv`로 둔다.
이미 파일이 있으면 덮어쓰지 말고 실제 측정 날짜가 들어간 새 파일명을 나에게 알린다.

### 3. 웨이퍼 모형 조립

- 센서를 비전도성 원판에 단단히 고정해 판 위에서 흔들리지 않게 한다
- 손으로 안전하게 기울이고 비틀 수 있게 한다
- 케이블에 여유 고리를 두고 케이블 무게가 모형을 끌지 않게 한다
- 모형의 앞쪽·왼쪽과 센서 X/Y축 방향을 표시하거나 사진/문서로 기록한다
- 조립 후 평평한 상태를 다시 읽어 roll/pitch 기준값을 기록한다

### 4. 정지 드리프트 3분

1. 최종 모형을 평평하고 진동이 적은 책상에 놓는다.
2. 포트 연결로 보드가 리셋되면 시작 보정 동안 건드리지 않는다.
3. 첫 정상 샘플 후 30초 안정화하고 이어서 180초 기록한다.
4. 기록 내내 센서와 책상을 건드리지 않는다. 사용자에게 시작 전에 확인하고 완료를 알려준다.
5. `data/raw/drift_2026-09-13.csv`에 WME 원본을 저장한다.
6. 다음 숫자를 그대로 계산해 보고한다.
   - roll 흔들림 폭 = 최댓값−최솟값
   - pitch 흔들림 폭 = 최댓값−최솟값
   - yaw 1분 밀림 = 60초 근처 값−시작값
   - yaw 3분 밀림 = 마지막 값−시작값
   - 기록 시간, 샘플 수, 평균 Hz, 최대 간격
7. 사용자가 측정 중 손대지 않았는지, 핀·케이블이 안정적이었는지도 사실대로 기록한다.

### 5. 회전 되돌아오기 시험 — 실제 yaw 판정에 가장 중요

가능하면 전체 원본을 `data/raw/yaw_return_2026-09-13.csv`에 저장한다.

1. 모형과 책상에 시작 방향 기준선을 표시한다.
2. 시작 yaw를 기록한다.
3. 한 방향으로 약 90° 비틀었다가 기준선까지 정확히 되돌린다.
4. 멈춘 뒤 yaw를 기록한다. 한 방향 3회 반복한다.
5. 반대 방향도 3회 반복한다. 총 6회다.
6. 각 회차마다 시작 yaw, 복귀 yaw, `복귀−시작` 잔류값을 기록한다.
7. 잔류값 6개의 절댓값 최댓값을 계산한다.
8. 측정 도중 임의 재영점이나 값을 숨기는 보정을 하지 않는다. 재부팅했다면 세션을 나누어 명시한다.

### 6. 모형 고정 후 축 부호 확인

- 모형의 왼쪽 가장자리를 낮췄을 때 roll 변화가 `+`인지 `−`인지
- 모형의 앞쪽(사용자에게서 먼 쪽) 가장자리를 낮췄을 때 pitch 변화가 `+`인지 `−`인지
- 위에서 봤을 때 시계 방향으로 비틀었을 때 yaw 변화가 `+`인지 `−`인지

평평한 시작값과 동작 후 값을 함께 남기고, `hardware/README.md`의 부호 표에 적는다.
고정 방향이 바뀌면 이 결과도 바뀌므로 조립 이후 값만 FRONT에 전달한다.

### 7. 완성 모형 실측 세션 약 30초

사용자가 실제 조작처럼 모형을 손에 들고 기울이고 비트는 동작을 약 30초 기록한다.
`data/raw/session_2026-09-13.csv`에 저장한다. 판정용 분석 자료가 아니라
“센서가 부착된 교육용 컨트롤러로 실제 측정했다”는 발표·문서 근거다.

## HEADER 판정 기준 — SENSOR는 적용하지 말고 숫자만 전달

yaw 센서를 회전 입력으로 쓰려면 HEADER가 아래 두 값을 확인한다.

1. 정지 3분 yaw 밀림의 절댓값 ≤ 3°
2. 회전 복귀 6회의 잔류 yaw 절댓값 최댓값 ≤ 2°

수평 판정 허용 범위는 roll/pitch 흔들림 폭을 보고 HEADER가 정한다. 현재 프론트 임시값은 ±2.0°다.
SENSOR는 통과·실패·버튼 사용을 결정하지 않고 **실측 숫자와 측정 조건만 보고한다.**

## 반드시 지킬 기록 원칙

- 실제 센서에서 읽고 파일로 남긴 숫자만 “실측”이라고 쓴다
- 짧은 화면 관찰, 합성 입력, 가상 시리얼 결과를 공식 측정값으로 섞지 않는다
- 못 한 항목은 “미측정”, 중단된 기록은 “부분 기록·판정 불가”로 쓴다
- 포트가 끊기거나 보드가 리셋되면 그 사실을 숨기지 않는다
- 원본 CSV를 수동으로 고치거나 나쁜 구간을 설명 없이 제거하지 않는다
- 최종 출력 규격과 50Hz를 복구·검증한 뒤 작업을 끝낸다

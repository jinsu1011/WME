# 계획 세션 프롬프트 — 제출물 문서 작성

---

한국어로 답해줘. 나는 코딩 경험이 거의 없는 SKALA 교육생이고, 3일짜리 AI 웹서비스 미니 프로젝트를 하는 중이야. 이 대화는 **계획 세션**이야. **제출물 문서 작성**을 담당해.

서비스명은 **WME — We Make Experts** 로 확정됐어.

## 시작 전에 읽을 것

1. `PROJECT_HEAD.md` — 제품 정의, 포지셔닝, 지켜야 할 원칙
2. `기획/PROGRESS.md` — 완료·진행 중·다음 작업
3. `기획/설계/DB설계.md` — 이미 작성 완료된 문서. **같은 밀도와 형식으로 맞춘다**
4. `web/frontend/src/api/index.ts` — API 명세의 기준
5. `web/frontend/src/types/index.ts` — 데이터 구조의 기준

## 내 담당

**쓰기**: `기획/설계/`, `제출/`
**읽기만**: 나머지 전부. 코드는 고치지 않는다.

## 할 일

### 1순위 — `기획/설계/API명세서.md`

`web/frontend/src/api/index.ts` 의 함수들과 `기획/설계/DB설계.md` 를 근거로 작성한다.
REST 10개 + WebSocket 1개. 각 경로마다:

- 역할, 요청(파라미터·본문·필수 여부), 응답 예시(JSON), 오류 코드와 상황, FE가 그 오류를 어떻게 처리하는지

오류 코드: 404 대상 없음 / 409 준비 중 과정·잘못된 상태 전환 / 422 입력·근거 오류 / 503 센서·AI 사용 불가

### 2순위 — `제출/프로젝트기술서.md`

8장 구성으로 초안. ①개요·사용자 ②문제·B2B 가치 ③과정·학습 흐름 ④FE 설계 ⑤센서·AI ⑥시스템·DB/API ⑦검증·구현 범위 ⑧일정·확장.
나중에 PDF로 내보낸다.

### 하지 말 것

`기획/설계/화면설계.md` 는 **아직 쓰지 않는다.** FRONT 세션이 화면을 고치는 중이라 지금 쓰면 틀린 문서가 된다.

## 반드시 지킬 것

- **구현하지 않은 것을 구현했다고 쓰지 않는다.** 실제 코드를 읽고 적는다.
  계획한 것은 "계획"이라고 명시한다
- 검증하지 않은 수치(정확도 95%, 교육시간 50% 감소 등)를 쓰지 않는다
- 포지셔닝을 지킨다: **실장비 대체가 아니라 투입 전 판단 훈련**
- 모형은 교육용 모형이라고 명시한다
- 작업이 끝나면 `기획/세션/로그/계획.md` 맨 위에 한 칸 추가한다 (다른 문서는 건드리지 않는다)

시작하기 전에 무엇을 어떤 순서로 할지 짧게 말하고 시작해줘.

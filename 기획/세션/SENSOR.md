# SENSOR 세션 프롬프트 — 펌웨어 · 데이터 수집 · 이상 탐지

---

한국어로 답해줘. 나는 코딩 경험이 거의 없는 SKALA 교육생이고, 3일짜리 AI 웹서비스 미니 프로젝트를 하는 중이야. 이 대화는 **SENSOR 세션**이야. 센서 장치와 이상 탐지 모델을 담당해.

## 시작 전에 읽을 것

1. `PROJECT_HEAD.md` — 제품 정의, 확정된 결정, 지켜야 할 원칙
2. `기획/PROGRESS.md` — 완료·진행 중·다음 작업
3. `hardware/README.md` — 부품과 배선 상태
4. `data/README.md` — 데이터 폴더 규칙

## 내 담당

**쓰기**: `hardware/`, `data/` (단 `data/local/` 은 BACK 담당)
**읽기만**: 나머지 전부

## 실습 장치

MPU6050(GY-521)을 작은 판에 단단히 붙이고, 그 위에 원형 모형을 올린다.
장비가 이동한 뒤 **안정화되는 상태**를 교육용으로 모사한 것이다.

- 정상: 천천히 움직인 뒤 안정적으로 정지
- 이상: 정지 후에도 작은 흔들림이 남거나 기준 자세와 다르게 유지
- 관측 대상: **동작 종료 이후의 안정화 구간만.** 이동 구간은 첫 버전의 판정 대상이 아니다

## 작업 순서

### 1. 배선과 수신 확인
보드 모델과 모듈 전압을 먼저 확인한 뒤 핀을 정한다. 기본은 VCC·GND·SCL·SDA 네 가닥.
`hardware/firmware/` 에 시리얼로 `시간(ms), ax, ay, az, gx, gy, gz` 를 내보내는 최소 스케치.

### 2. 정상 데이터 수집
- 부착 상태·조작 방식·관측 조건을 **고정**하고 여러 세션 수집
- `data/raw/train_normal/` 학습용, `data/raw/validation/` 임계값 조정용, `data/raw/test/` 최종 확인용
- 세션마다 수집 조건(부착 상태, 날짜, 장소)을 같은 이름의 `.txt` 로 남긴다

### 3. 이상 후보 탐지
- 안정화 구간을 짧은 시간 창으로 나눈다 (초기 후보: 1초 창 / 0.5초 간격)
- 창마다 roll·pitch 의 중앙값과 변동, 각속도 크기의 RMS 등 소수 특징을 계산
- IsolationForest 한 종류만 학습. 검증 세션에서 임계값과 연속 창 조건을 정한다
- 새 정상 세션의 오탐, 의도적으로 흔든 세션의 탐지를 각각 확인해서 기록한다
- 모델 파일과 특징 설정·임계값·사용한 데이터 목록·버전을 `data/models/` 에 함께 저장

### 4. 발표용 재생 데이터
`data/demo/` 에 정상 1세션 + 이상 1세션. 실시간 시연이 실패했을 때의 대비책이다.

## 반드시 지킬 것

- **한 기록의 겹치는 시간 창을 무작위로 나눠 "독립 검증"이라고 하지 않는다.** 세션 단위로 나눈다
- 학생 실습 데이터를 정상 학습 데이터에 자동으로 넣지 않는다
- 가속도를 그대로 기울기로 쓰지 않는다. 가속도와 자이로를 함께 써서 추정한다
- 누락 데이터·연결 끊김을 정상으로 처리하지 않는다
- **손으로 만든 흔들림은 실제 반도체 장비의 고장 데이터가 아니다.** 정확도 수치를 함부로 말하지 않는다
- **모델이 짧은 시간 안에 안정되지 않으면 통계 기준 비교로 내린다.** 정상 기록의 평균·편차와
  비교하는 방식이다. 그때는 "정상 패턴 학습 완료" 표현을 전부 없애고 문서에 반영한다.
  손으로 정한 임계값을 학습된 모델이라고 부르지 않는다
- 모델을 여러 개 연속으로 추가하지 않는다. 하나로 안 되면 축소한다
- 계획한 것과 실제로 측정해서 확인한 것을 구분해서 말한다
- 작업이 끝나면 `기획/PROGRESS.md` 를 갱신한다

시작하기 전에 무엇을 어떤 순서로 할지 짧게 말하고 시작해줘.

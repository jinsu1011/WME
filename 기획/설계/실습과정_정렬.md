# 실습 과정 정의 — 포토공정 입문 · 마스크·웨이퍼 정렬 실습

> 확정: 2026-09-12. **이전의 「웨이퍼 스테이지 이상 대응 실습」을 대체한다.**
> 이 문서가 실습 과정에 대한 기준이다. 화면·DB·AI는 전부 여기에 맞춘다.

## 1. 무엇을 가르치는가

반도체 포토공정에서는 노광 전에 **마스크와 웨이퍼의 패턴 위치를 맞춰야 한다.**
연구·교육용 **수동 마스크 얼라이너**에서는 작업자가 현미경 화면의 정렬 마크를 보면서
조작기로 웨이퍼의 위치와 회전을 직접 조정한다.

참고: [EPFL CMI — EVG 610 마스크 얼라이너](https://www.epfl.ch/research/facilities/cmi/equipment/photolithography/evg-610/)

WME는 신입 기술자가 **이 정렬 원리와 조작 순서를 연습**할 수 있게 한다.

### 발표용 설명 문장

> "반도체 포토공정에서는 노광 전에 마스크와 웨이퍼의 패턴 위치를 맞춰야 합니다.
> 수동 마스크 얼라이너에서는 작업자가 화면을 보면서 직접 위치와 회전을 조정합니다.
> 저희는 신입 기술자가 이 정렬 원리를 연습할 수 있도록,
> 웨이퍼 모형과 웹 화면을 연결한 교육 과정을 만들었습니다."

### 반드시 밝힐 것

**센서를 붙인 웨이퍼 모형은 실제 장비의 조작기를 대신하는 교육용 컨트롤러다.**
실제 공정에서 웨이퍼를 손으로 기울여 정렬한다는 뜻이 아니다. 화면·문서·발표에 모두 명시한다.

## 2. 과정명

`포토공정 입문 — 마스크·웨이퍼 정렬 실습`

## 3. 실습 구성

| | 내용 |
|---|---|
| **화면** | 고정된 **마스크 정렬 마크**와 어긋나 있는 **웨이퍼 정렬 마크**를 함께 보여준다 |
| **조작** | 모형을 기울이면 → 화면 속 웨이퍼가 X/Y 로 이동. 회전(θ)은 화면 버튼으로 시작 |
| **목표** | 두 마크를 허용 오차 안으로 겹친다 |
| **결과** | 정렬 오차 · 소요 시간 · 보정 과정을 보여주고 AI가 연습 피드백을 준다 |

조작 매핑은 **조이스틱 방식**이다. 기울기(roll/pitch)를 이동 속도로 해석한다.
기울기가 곧 위치라는 뜻이 아니며, 이것도 교육용 컨트롤러임을 화면에 표시한다.

## 4. 학습 목표

1. 노광 전 정렬이 왜 필요한지 설명한다.
2. 정렬 마크를 보고 **어긋난 방향과 양**을 읽는다.
3. 위치와 회전을 **순서대로** 조정해 허용 오차 안에 맞춘다.
4. 자신이 그 순서로 조정한 이유를 설명하고, 결과를 기록한다.

## 5. 단계

| 단계 | 학습자가 하는 것 | 화면이 주는 것 |
|---|---|---|
| 1. 개념 | 포토공정과 정렬의 역할 확인 | 짧은 설명과 그림 |
| 2. 마크 읽기 | 정렬 마크와 허용 오차 기준 확인 | 기준 예시, 어긋난 예시 |
| 3. 정렬 실습 | 모형으로 X/Y 조정, 버튼으로 θ 조정 | 실시간 마크 겹침, 현재 오차 |
| 4. 제출 | 정렬 확정 + 조정 순서와 이유 작성 | 확정 버튼, 짧은 입력 폼 |
| 5. 피드백 | 오차·시간·보정 경로와 AI 피드백 확인 | 결과 요약, 재실습 |

## 6. 측정하는 것 (전부 기록에서 계산)

| 지표 | 설명 |
|---|---|
| `final_dx`, `final_dy` | 최종 위치 오차 (화면 단위 px, 환산 표기 µm) |
| `final_dtheta` | 최종 회전 오차 (도) |
| `duration_ms` | 정렬에 걸린 시간 |
| `adjustment_count` | 보정 동작 횟수 |
| `overshoot_count` | 목표를 지나쳤다가 되돌아온 횟수 |
| `converged` | 허용 오차 안에 들어왔는지 |

**허용 오차는 과정 설정값이다.** 실제 장비의 정렬 정밀도가 아니다.

## 7. 평가 기준 (루브릭 4개)

| # | short | 내용 |
|---|---|---|
| 1 | 정렬 정확도 | 최종 오차가 허용 범위 안에 들어왔는가 |
| 2 | 조정 순서 | 위치를 먼저 맞추고 회전을 정리하는 등 절차를 지켰는가 |
| 3 | 보정 효율 | 과잉 보정 없이 수렴했는가 |
| 4 | 설명·기록 | 왜 그 순서로 조정했는지 설명했는가 |

4번이 있어야 **손재주 평가가 아니라 교육**이 된다. 1~3번만이면 게임 점수가 된다.

## 8. AI의 역할

| | 역할 | 필요한 것 |
|---|---|---|
| **AI 1 — 정렬 경로 분석** | 보정 궤적에서 과잉 보정·축 간섭·수렴 패턴을 찾아 근거로 제시 | 규칙 기반. **모델 학습 불필요** |
| **AI 2 — LLM 학습 피드백** | 오차 궤적 + 학습자 설명을 보고 피드백하고 루브릭 채점 | LLM API 키 |

**컨셉 변경으로 IsolationForest 학습이 필요 없어졌다.** 발표장에서 모델이 오탐할 위험이
사라지고, 대신 계산이 명확한 규칙 기반 분석이 들어간다. 리스크가 크게 줄었다.

## 9. 데이터 구조 변경점

기존 스키마에서 바뀌는 부분만 적는다. 테이블 6개 구성은 그대로다.

| 테이블 | 변경 |
|---|---|
| `measurements` | `roll`,`pitch` 유지(컨트롤러 입력) + 화면 웨이퍼 상태 `wafer_x`,`wafer_y`,`wafer_theta` 추가. `anomaly_score` 제거 |
| `events` | `type`: `anomaly_candidate` → `adjustment`(보정 구간) / `overshoot`(과잉 보정) / `manual` |
| `attempts.summary_json` | 6절의 지표로 교체 |
| `courses.rubric_json` | 7절의 루브릭 4개로 교체 |
| `courses.content_json` | 5절 단계, 허용 오차 설정값 추가 |

## 10. 센서가 없을 때

**이 과정은 센서 없이도 완전히 동작한다.** 키보드 방향키 또는 화면 슬라이더를 컨트롤러로 쓰면
정렬 실습·채점·피드백이 전부 그대로 된다. 센서는 **입력 장치를 바꾸는 것**일 뿐이다.

이전 컨셉에서는 센서가 없으면 실습 자체가 성립하지 않았다. 이 점이 가장 큰 개선이다.

입력 소스도 화면에 표시한다: `키보드 조작` / `모형 컨트롤러`.

## 11. 남은 결정

- [ ] 허용 오차 기준값 (예: 위치 ±4px, 회전 ±1.0°)
- [ ] 기울기 → 이동 속도 변환 계수
- [ ] 회전을 센서로 확장할지, 버튼으로 유지할지
- [ ] 카탈로그의 나머지 과정 이름을 포토공정 맥락으로 맞출지

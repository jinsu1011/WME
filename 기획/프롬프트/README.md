# 이어서 할 프롬프트

**이 폴더의 파일은 설명서가 아니라 프롬프트 자체다.**
파일 하나를 통째로 복사해서 새 대화(Claude / Codex 등)의 첫 메시지에 붙여넣으면 그 역할로 시작한다.

## 어느 걸 고르나

| 파일 | 언제 쓰나 | 건드리는 폴더 |
|---|---|---|
| `HEADER.md` | 문서·발표자료를 쓸 때, 결정이 필요할 때 | `PROJECT_HEAD.md`, `기획/`, `제출/` |
| `FRONT.md` | 화면을 고칠 때 | `web/frontend/` |
| `BACK.md` | 서버·DB·LLM을 고칠 때 | `web/backend/`, `data/local/` |
| `SENSOR.md` | 아두이노·측정 작업을 할 때 | `hardware/`, `data/` |

## 규칙 두 개만 지키면 사고가 안 난다

1. **폴더 소유권** — 세션마다 건드릴 폴더가 정해져 있다. 남의 폴더는 읽기만 한다
2. **결정은 HEADER에서만** — 이름·범위·구조 변경이 다른 대화에서 나오면
   거기서 정하지 말고 HEADER로 가져온다. 서로 다른 결정을 내리는 게 유일한 실패 원인이다

## 시작 전 / 끝난 뒤

```bash
git pull                                    # 시작할 때
git add -A && git commit -m "..." && git push   # 끝날 때 (사용자가 직접)
```

작업이 끝나면 각 대화가 `기획/작업로그/<역할>.md` 맨 위에 한 칸 추가한다.
자기 파일만 쓰므로 충돌하지 않는다. HEADER가 그 로그를 모아 `기획/PROGRESS.md` 와
루트 `이어서작업.md` 를 갱신한다.

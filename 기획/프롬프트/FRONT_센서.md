## 할 일 — 이 순서로

### 1. 연결 안정화 (HEADER 가 코드에서 찾은 원인)

**(a) 포트가 안 닫히는 문제**
- 실습 화면을 나가거나 재실습해도 포트를 닫지 않는다 → 다시 연결하면 `The port is already open`.
  → `AlignmentExercise.tsx` 에서 화면이 사라질 때(useEffect 정리 함수) `tilt.disconnect()` 호출
- `TiltSource.disconnect()` 가 수신 파이프(`pipeTo`)가 풀리기 전에 `port.close()` 를 불러 닫기가 조용히 실패할 수 있다.
  → `reader.cancel()` 후 **`pipeTo` 약속을 기다린 뒤** `port.close()`. 닫기 실패를 삼키지 말고 콘솔에 남긴다
- 이미 열린 포트를 다시 고르면(`open` 이 already open 으로 실패) 그 포트를 닫고 한 번 다시 연다

**(b) 보드가 보내는 안내 줄을 버리는 문제**
- 지금 `WME,` 가 아닌 줄은 전부 버린다 → 보정 중·보정 실패가 화면에 안 보인다
- `INFO,`/`ERR,` 줄을 읽어 상태로 보여준다. 문구는 `src/data/controllerSettings.ts` 에 둔다. 최소:
  - `INFO,KEEP_STILL_CALIBRATING` → "센서 보정 중입니다. 모형을 책상에 두고 손을 떼세요"
  - `ERR,KEEP_STILL_RETRY` → "움직임이 감지되어 다시 보정합니다. 손을 떼세요"
  - `INFO,READY` → 안내 지움
  - `ERR,MPU6050_NOT_FOUND`·`ERR,I2C_READ_FAILED` → "센서 배선을 확인하세요. USB 를 다시 꽂은 뒤 연결하세요"
  - 그 외 줄 이름은 SENSOR 로그를 따른다
- `WME` 파싱 규칙(`parseLine`)은 바꾸지 않는다

**(c) 값이 안 오는 상태를 알려주기**
- 연결 후 **5초** 동안 `WME` 줄이 없으면(또는 마지막 수신 후 2초 이상 끊기면) 경고: "센서 값이 들어오지 않습니다" + 원인 후보(보정 중 / 다른 프로그램이 포트 사용 / USB 재연결) + `키보드로 진행`

**(d) 연습 시작 전에 고르게 안내**
- 입력 출처는 `연습 시작` 전에만 바꿀 수 있다(이건 유지). 대기 상태에서 "모형 컨트롤러를 쓰려면 연습 시작 전에 선택·연결하세요" 한 줄

### 2. 회전을 "각도 그대로" 방식으로 (★ 결정 15 ★)

**지금**: 모형 yaw 를 **속도**로 해석 — 비틀어 두면 계속 돈다 (`TiltSource.read()` → `vTheta`)
**바꿈 (센서 모드만)**: 모형을 돌린 **각도만큼** 화면 웨이퍼 θ 가 돈다.

규칙:
- `영점 잡기` 누른 순간: `yawBase = 현재 yaw`, `thetaBase = 현재 웨이퍼 θ`
- 매 프레임: `θ = thetaBase + (현재 yaw − yawBase) × 부호`
  - 부호는 SENSOR 로그의 축 부호 표를 보고 "위에서 보고 시계 방향으로 돌리면 화면도 시계 방향"이 되게 정한다
- **수평이 깨진 동안은 θ 를 멈춘다(기존 회전 잠금 유지).** 다시 수평이 되면 그 순간 `yawBase`·`thetaBase` 를 새로 잡아 **튀지 않게** 한다
- 센서 모드에서 Q/E(키보드 회전)를 쓰면 `thetaBase` 에 더해 같이 동작하게 한다
- θ 범위 제한(±45°)·위치 X/Y(방향키)·전송 주기·저장 값 구조는 그대로
- 속도 방식 코드(`yawToVelocity`, `yaw*` 계수)는 **지우지 않고** 설정 한 줄로 고를 수 있게 둔다:
  `src/data/controllerSettings.ts` 에 `YAW_MODE: 'absolute' | 'velocity' = 'absolute'` + 주석 `⚠️ HEADER 결정 15 — 서버 과정 설정(control)에 자리가 생기면 옮긴다`
- 자이로 특성상 가만히 둬도 조금씩 밀린다 → 센서 패널에 "회전이 어긋나면 모형을 맞춘 뒤 `영점 잡기`" 한 줄

### 3. 기울기 방향 확인
- 3D 스테이지 기울기(`readPose` 의 roll/pitch)가 모형과 **같은 방향**인지 SENSOR 부호 표와 실제로 맞춰 본다
- 반대면 부호만 고친다 (계산 방식은 바꾸지 않는다)

### 4. 실제 센서로 확인 — 결과를 표로

| 확인 | 기대 |
|---|---|
| 첫 연결 | 연결 → "보정 중" 안내 → 손 떼면 사라지고 값이 바뀜 |
| 보정 중 흔들기 | "다시 보정합니다" → 손 떼면 스스로 정상 |
| 다시 연결 | `연결 끊기` → `모형 컨트롤러 연결` 이 오류 없이 됨 |
| 재실습 | 결과 → 재실습 → 다시 연결이 오류 없이 됨 |
| 좌우·앞뒤 기울기 | 3D 스테이지가 같은 방향으로 같은 만큼 기움, 부드러움 |
| 수평 판정 | ±2° 안 `평행 확보`, 밖이면 `기울어짐` + 회전 잠김 |
| 회전 | 모형을 시계 방향 30° 돌리면 화면 웨이퍼도 시계 방향 약 30°, 되돌리면 되돌아옴 |
| 잠금 후 복귀 | 기울였다가 수평으로 오면 θ 가 튀지 않음 |
| USB 뽑기 | "연결이 끊어졌습니다" + `키보드로 진행` |
| 5초 무수신 | 경고 문구 |
| 키보드 모드 | 방향키·Q/E·W/A/S/D 실습 전체가 전과 똑같이 됨 (회귀) |
| 끝까지 | 확정 → 노광·현상 → 제출 → 결과 화면까지 센서 모드로 1회 완주 |

- 잘 되는 30초를 휴대폰으로 녹화하라고 나에게 권한다 (발표 백업)
- 타입 검사·빌드·린트: `npm --prefix web/frontend run build`, `npm --prefix web/frontend run lint`

## 반드시 지킬 것
- `web/frontend` 만 쓴다. `hardware/`, `web/backend`, `기획/`, `제출/` 은 읽기만
- **센서 연결·회전 방식 외에는 고치지 않는다.** M1·M2·캡처·다른 화면은 회사 FRONT 세션 몫 (같은 파일을 두 곳에서 고치면 충돌한다)
- 키보드만으로 실습 전체가 되는 상태 유지, mock 모드 유지
- 서버로 보내는 값 구조(`roll:0, pitch:0, waferX/Y/Theta`)는 바꾸지 않는다
- 실제 센서로 브라우저에서 확인한 것만 "확인했다"고 적는다
- 끝나면 `기획/작업로그/Front.md` 맨 위에 기록 (제목에 "센서 연결"). git commit 은 하지 않는다 — **내가 끝나자마자 커밋·푸시한다** (회사 FRONT 가 pull 받아야 함)

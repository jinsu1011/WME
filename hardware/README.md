# hardware — WME 교육용 센서 컨트롤러

## 측정 결과 — 2026-09-13 평평한 자세 진단 (모형 부착 전)

사용자는 납땜을 완료하고 센서를 책상에 평평하게 놓았다고 보고했다. 모형에는 아직 부착하지 않았다.
임시 진단 펌웨어로 가속도 3축(g 단위)과 각도를 함께 읽었다. 정상 진단 샘플 268개,
보드 시간 3067~8408ms(5.341초), 평균 49.991Hz, 오류 메시지 없음.

| 항목 | 평균 | 최솟값 ~ 최댓값 |
|---|---:|---|
| ax (g) | -0.00414 | -0.0084 ~ -0.0005 |
| ay (g) | -0.06893 | -0.0732 ~ -0.0643 |
| az (g) | 1.02572 | 1.0200 ~ 1.0308 |
| roll (°) | -3.84463 | -4.09 ~ -3.60 |
| pitch (°) | 0.23060 | 0.03 ~ 0.47 |

출력된 가속도에서 별도로 다시 계산한 pitch와 보드 출력의 최대 차이는 0.00717°였다
(가속도 소수 4자리, 각도 소수 2자리 출력의 반올림 차이를 포함).
현재 코드에는 60° 제한이 없고, 현재 pitch도 60°에 고정되지 않는다. 현재 자세의 pitch 계산은 가속도와 일치한다.
이전 60° 샘플에는 동시 가속도 기록이 없으므로 당시 원인이 실제 자세였는지는 확정할 수 없다.
roll 약 -3.84°는 가속도 ay의 치우침과 일치한다. 좌우 잔여 기울기와 가속도계 영점 오차를 아직 분리하지 못했다.
임의 영점 보정이나 계산식 변경은 하지 않았다. 여러 각도로 움직이는 연속성 시험과 모형 고정 후 확인은 아직 남아 있다.

진단 후 최종 WME 50Hz 펌웨어 복구 업로드 성공. 정상 WME 121개, DBG 0개, 오류 없음으로 복구 확인.
복구 후 실제 예: `WME,3067,-3.70,0.11,0.00`, `WME,5468,-3.84,0.29,-0.00`.
이번 결과는 짧은 자세 진단이며 **3분 드리프트·회전 복귀 6회·축 부호·모형 실측 30초는 미측정**이다.

최신 HEADER 지시가 아래 이전 설명보다 우선한다: roll/pitch→수평(평행), yaw→회전, X/Y→키보드.
드리프트는 안정화 30초 후 3분 기록, yaw 변화는 1분·3분 둘 다 보고한다. SENSOR는 숫자만 보고하고 채택 판정은 HEADER가 한다.
아래의 1분 기록·1° 자동 판정 안내와 현재 Python 도구는 이전 버전이므로, 새 측정 전에 3분·숫자 보고 방식으로 갱신해야 한다.

## 1. 현재 상태와 확인 범위

2026-09-13 기준 부품 도착. 실물 사진에서 Arduino UNO / ATMEGA328P, 센서 기판의 MPU-6050 표시를 확인했다.
Arduino IDE 2.3.5에서 `Arduino UNO`, `/dev/cu.usbmodem1101` 인식 확인: USB 데이터 통신이 가능한 케이블이다.
UNO는 5V 로직이다. **WME 업로드와 MPU6050 인식·실제 각도 수신 성공. 축 부호와 1분 드리프트는 미측정이다.**
처음 업로드/센서 식별은 실패했지만, USB 재연결 후 업로드가 성공했고 사용자 재확인 요청 뒤 보드 리셋에서 센서가 인식됐다.
115200 baud로 실제 `INFO,KEEP_STILL_CALIBRATING`, `INFO,READY`와 WME 샘플 169개를 받았다.
수신 샘플의 보드 시각 3067~6427ms(3.360초), 평균 50.0Hz, 샘플 간격 19~21ms. 해당 짧은 구간의 관측이며 장시간 안정성 검증은 아니다.
실제 예: `WME,3067,-2.70,60.00,0.00`. pitch 약 60°로 평평한 측정 자세인지 확인이 필요하다.
1분 정지 기록은 아직 없으므로 yaw 드리프트 합격/불합격은 판정하지 않았다.

센서는 GY-521 계열 형태지만 정확한 모듈 모델/판매 사양 및 레귤레이터 부품명은 미확인이다.
최초 사진의 핀 구멍은 비어 있었다. 사용자는 이후 납땜 없이 핀헤더·점퍼선을 연결했다고 보고했다.
납땜 완료나 안정적인 전기 접촉을 확인했다는 의미가 아니다. 헐거운 연결은 통신 끊김의 원인이 될 수 있다.

**센서를 붙인 웨이퍼 모형은 실제 장비의 조작기를 대신하는 교육용 컨트롤러다.
실제 공정에서 웨이퍼를 손으로 기울여 정렬한다는 뜻이 아니다.**

## 3. 배선표 — 모듈 전압 사양 확인을 조건으로 사용

**배선을 바꿀 때는 USB와 외부 전원을 모두 뺀다.** 핀 위치보다 기판에 인쇄된 핀 이름을 우선한다.

| UNO 쪽 핀 | MPU6050 모듈 쪽 핀 | 설명 |
|---|---|---|
| `5V` | `VCC` | **모듈 VCC가 5V 입력을 지원하는 경우에만** 사용 |
| `GND` | `GND` | 두 보드의 전기적 기준 연결 |
| `A4` (ANALOG IN) | `SDA` | I2C 데이터선. DIGITAL 4와 다름 |
| `A5` (ANALOG IN) | `SCL` | I2C 타이밍 신호선. DIGITAL 5와 다름 |

`XDA`, `XCL`, `INT`는 이번에 연결하지 않는다. `AD0`는 모듈 기본 설정을 쓰며 펌웨어는 0x68/0x69를 모두 확인한다.
UNO의 `VIN`이나 `AREF`를 센서 VCC로 쓰지 않는다.

### 전압 확인에서 중요한 점

- MPU6050 **칩 자체**의 전원 범위는 2.375~3.46V다. 칩에 5V를 직접 공급하는 배선은 아니다.
- `5V → VCC`는 모듈에 맞는 전압 조절 회로가 있고 판매 사양에서 5V 입력을 지원할 때만 유효하다.
  참고 회로도에 적힌 “5V compatible” 문구는 실제 모듈 사양을 대신하지 않는다.
- 전원 레귤레이터는 SDA/SCL 신호를 자동으로 3.3V로 변환하지 않는다. 모듈의 I2C 풀업(신호선을 높은 전압으로 올리는 저항)이
  센서 허용 전압에 연결되는지 판매 회로도/사양으로 확인한다. 현재 모듈의 풀업 연결 전압은 미확인이다.
- 제공 스케치는 UNO의 5V 내부 SDA/SCL 풀업을 끈다. 따라서 센서 허용 전압에 연결된 모듈 외부 풀업이 필요하다.
  이는 전압 변환기를 추가한 것과 같지 않다. 5V 외부 풀업이 있는 모듈에는 별도 호환성 검토가 필요하다.
- 핀을 구멍에 끼운 것만으로 납땜과 같은 고정·접촉을 보장하지 않는다. 전압 호환성과 접촉을 확인하기 전에는
  이 표를 근거로 “실제 배선 검증 완료”라고 기록하지 않는다. 추가 부품/구조 변경이 필요하면 HEADER에 전달한다.

## 4. Arduino IDE에서 스케치 열기·보드·포트 설정

1. **파일 → 열기**에서 `hardware/firmware/wme_sensor/wme_sensor.ino`를 연다.
   폴더와 파일 이름이 모두 `wme_sensor`여야 한다. 기존 ESP32 프로젝트를 덮어쓰지 않는다.
2. IDE 상단 **보드 선택(Select Board)** 또는 **도구 → 보드 → Arduino AVR Boards → Arduino Uno**를 선택한다.
   예전에 열려 있던 ESP32 프로젝트의 보드 설정을 그대로 사용하면 안 된다.
3. **도구 → 포트 → `/dev/cu.usbmodem1101`**를 선택한다. USB를 다시 꽂으면 이름이 달라질 수 있으므로 실제 UNO 표시를 확인한다.
4. 센서 라이브러리는 설치하지 않는다. 설치된 Arduino AVR Boards 코어의 `Wire.h`만 사용한다.
5. **확인(✓)**은 컴파일이다. **업로드(→)**는 보드의 기존 프로그램을 교체한다. 후속 USB 재연결 후 WME 업로드에 성공했고, 이후 재확인에서 센서값 수신도 성공했다.
6. 실제 전압/접촉 확인 후 업로드할 때는 센서를 평평하게 고정하고 손대지 않는다. 시작 직후 약 2초간 영점을 계산한다.
7. **도구 → 시리얼 모니터**, 속도 **115200 baud**를 선택한다. 모니터를 열면 UNO가 리셋될 수 있으므로 다시 가만히 둔다.
8. `INFO,KEEP_STILL_CALIBRATING` 다음 `INFO,READY`, 이후 `WME,...`가 연속 출력되는지 확인한다.
   `ERR,...`가 나오면 정상 측정이 아니다. 오류별 안내는 아래를 따른다.
9. 기록 도구를 실행하기 전에 **시리얼 모니터·시리얼 플로터를 닫고**, 브라우저 Web Serial도 연결 해제한다.
   한 포트를 여러 프로그램에서 동시에 읽으면 기록을 잃는다.

## 5. 출력 규격과 계산 방식

```text
WME,<t_ms>,<roll>,<pitch>,<yaw>\n
```

형식 설명용 예시(실측값 아님): `WME,1240,-3.25,7.81,0.42`

| 항목 | 규격 |
|---|---|
| 접두사 | `WME,` 필수, 한 줄에 정상 샘플 하나 |
| t_ms | 보드 시작 후 경과 밀리초, 정수. 보정 시간을 포함하며 첫 샘플이 0일 필요 없음 |
| roll / pitch / yaw | 도(°), 소수점 둘째 자리 |
| 줄 끝 | LF (`\n`) 하나 |
| 시리얼 | 115200 baud, 8비트, 패리티 없음, 정지 비트 1개 |
| 출력 주기 | 정상 동작 시 20ms, 초당 50회 |
| 부팅/오류 | `INFO,` / `ERR,`로 시작. 정상 샘플로 취급하지 않음 |

- roll = `atan2(ay, az)`를 도로 변환. pitch = `atan2(-ax, sqrt(ay² + az²))`를 도로 변환한다.
  가속도계의 중력 방향을 사용하므로 빠르게 흔들거나 이동시키면 각도에 오차가 섞인다.
- yaw는 `(자이로 Z 각속도 - 시작 시 영점 오차) × 실제 경과 시간`을 누적한다.
  절대 나침반 방향이 아니며 시간이 지나면 밀릴 수 있다. ±180도 경계에서 값을 감지 않는다.
- 시작 시 약 2초간 자이로 영점을 한 번 계산한다. 이후 자동 영점 재설정은 하지 않아 드리프트가 기록에 남는다.
  큰 움직임은 검출하지만 느린 회전까지 모두 알아내지는 못하므로 보정 중 반드시 정지해야 한다.
- 센서 내부 갱신은 200Hz, 출력은 50Hz다. 가속도 ±2g, 자이로 ±250°/s, 내부 저역 필터를 사용한다.
- 전송 경로: **Arduino → USB 시리얼 → 브라우저(Web Serial API)**. 서버를 거치지 않는다.
- **FRONT 담당 변환**: roll→X 이동 속도, pitch→Y 이동 속도, yaw→회전 속도. 각도가 곧 위치가 아니다.
  SENSOR는 각도만 내보내며 웹 코드와 변환 계수를 수정하지 않는다.

## 6. 웨이퍼 모형 만들기

1. 센서 기판을 비전도성 판에 단단히 고정한다. 흔들림이나 기판 아래 금속 접촉이 없게 한다.
2. 모듈의 부품이 있는 면을 위로 두고, 표시된 X/Y축을 판에 옮겨 적는다. 판에 **앞 / 왼쪽** 화살표도 붙인다.
3. 케이블은 모형 근처에 여유 고리를 남긴다. 케이블 무게가 모형을 잡아당기지 않게 별도로 고정한다.
4. 보드와 점퍼선을 잡고 움직이는 대신 판을 천천히 기울인다. 센서를 뒤집거나 크게 흔드는 사용은 피한다.
5. 실제 부착 방향에 따른 부호는 8절에서 확인한다. 화면 방향에 맞추려고 여기서 펌웨어 부호를 임의 변경하지 않는다.

## 7. 가장 중요한 작업: 1분 드리프트 측정

현재 결과: **미측정**. 아래 명령은 사용자가 측정할 때 실행한다. 후속 연결 확인에서 정상 샘플 수신에 성공했지만, 1분 정지 기록은 아직 수행하지 않았다.

### 준비

- 위 절차로 스케치를 업로드하고 정상 WME 출력을 먼저 확인한다.
- 센서를 최종 모형에 고정한 채 평평하고 진동이 적은 책상에 놓는다. 케이블이 당기지 않게 한다.
- IDE 시리얼 모니터/플로터와 브라우저 시리얼 연결을 닫는다.
- 기록 명령 시작부터 완료까지 손을 대지 않는다. 시작 시 보드가 리셋되면 영점 보정도 다시 진행된다.

### 파일로 저장하기 — Mac 터미널

프로젝트 폴더에서 터미널을 열거나 다음처럼 이동한다(폴더 이름이 바뀌면 실제 경로 사용).

```bash
cd "/Users/kimjinsu/Library/Mobile Documents/com~apple~CloudDocs/SKALA/미니프로젝트1"
python3 data/capture_drift.py --port /dev/cu.usbmodem1101
```

추가 패키지 설치 없이 실행한다. 첫 정상 샘플 이후 **30초 안정화 + 60초 기록**, 보통 약 90~95초가 걸린다.
화면에 “저장 완료”가 나올 때까지 기다린다. 결과는 `data/raw/drift_2026-09-13.csv`에 저장된다.
헤더를 추가하지 않고 정상 `WME,...` 줄 그대로 저장한다. 50Hz라면 약 3001개(양 끝 포함), 보드 시간 차이 60000ms다.
안정화 30초는 온도 안정 완료를 보장하는 인증 기준이 아니다. 결과는 해당 준비 조건에서의 측정이다.

기존 파일은 덮어쓰지 않는다. 재측정하려면 새 이름을 쓴다.

```bash
python3 data/capture_drift.py --port /dev/cu.usbmodem1101 --output data/raw/drift_2026-09-13_repeat2.csv
```

중단하려면 Ctrl+C를 누른다. 중단·실패 시 남은 파일은 **부분 기록**이며 결과로 보고하지 않는다.
포트가 없으면 연결을 확인하고, 포트 사용 중이면 IDE/브라우저의 시리얼 연결을 닫는다.

### 세 숫자 계산하기

```bash
python3 data/analyze_drift.py data/raw/drift_2026-09-13.csv
```

출력은 다음 세 숫자와 품질 확인 정보다.

1. roll 흔들린 폭 = 최댓값 - 최솟값
2. pitch 흔들린 폭 = 최댓값 - 최솟값
3. yaw 밀림 = 끝값 - 시작값 (양수·음수 표시)

판정은 **`abs(yaw 밀림) > 1.00°`이면 회전은 화면 버튼**이다. 정확히 ±1.00°는 “초과”가 아니다.
1.00° 이내여도 모든 동작 정확도를 보장하는 것은 아니며, 정지 드리프트 기준 충족 결과를 HEADER에 전달한다.
허용 오차 ±1.0°는 교육 과정 설정값이며 실제 장비의 정렬 정밀도가 아니다.

분석기는 60.000~60.100초 기록, 시각 증가, 평균 45~55Hz, 최대 샘플 간격 100ms 이하를 검사한다.
이 범위는 끊긴 기록을 잘못 판정하지 않기 위한 수집 품질 점검이며, 확정 전송 목표 50Hz나 회전 기준을 바꾸는 것이 아니다.
잘못된 형식, NaN/무한대, 짧은 기록, 중복/리셋 시각, 큰 끊김은 **판정 보류**로 종료한다.
실제로 책상을 움직이지 않았는지는 프로그램이 알 수 없으므로 사람이 확인해야 한다.

## 8. 기울임 방향 부호 확인 — 드리프트 측정과 따로 진행

1. 드리프트 수집을 끝낸 다음 IDE 시리얼 모니터를 115200으로 연다. 리셋 시 약 2초간 가만히 둔다.
2. 판의 **앞쪽 표시가 사용자에게서 멀어지는 방향**이 되도록 잡는다. 평평한 상태의 roll/pitch를 적는다.
3. “왼쪽으로 기울임”은 **판의 왼쪽 가장자리를 낮추는 것**으로 통일한다. 천천히 약 10° 기울이고 멈춘 뒤 값을 읽는다.
4. 평평할 때보다 roll이 커지면 `+`, 작아지면 `-`다. 기울어진 상태의 숫자 자체보다 **평평한 상태와의 차이**를 본다.
5. 다시 평평하게 놓고, “앞으로 기울임”은 **사용자에게서 먼 앞쪽 가장자리를 낮추는 것**으로 통일한다.
6. 같은 방식으로 pitch의 변화 부호를 기록한다. 반대 방향에서도 반대 부호로 변하는지 확인한다.
7. 좌우 동작에 pitch만 크게 변하면 축이 90° 돌아간 부착일 수 있다. 판 표시와 실제 축을 점검하고 결과를 FRONT/HEADER에 전달한다.

| 동작 | 평평할 때 값 | 기울인 뒤 값 | 변화 부호 | 상태 |
|---|---|---|---|---|
| 왼쪽 가장자리 낮추기 → roll | — | — | — | 미측정 |
| 오른쪽 가장자리 낮추기 → roll | — | — | — | 미측정 |
| 앞쪽 가장자리 낮추기 → pitch | — | — | — | 미측정 |
| 뒤쪽 가장자리 낮추기 → pitch | — | — | — | 미측정 |

화면 축 부호 보정은 FRONT가 담당한다. SENSOR는 실측값과 부착 방향을 전달하며 웹 파일을 수정하지 않는다.

## 9. 오류가 나올 때

| 시리얼 메시지 | 뜻과 다음 행동 |
|---|---|
| `ERR,MPU6050_NOT_FOUND` | 0x68/0x69에서 칩 식별 실패. 전원을 분리하고 전압 사양·핀 이름·접촉 상태 확인 |
| `ERR,RESET_FAILED`, `WAKE_FAILED`, `RATE_FAILED`, `RANGE_FAILED` | 설정 통신 실패. 배선/접촉 확인 후 리셋 |
| `ERR,KEEP_STILL_AND_RESET` | 초기 보정 중 큰 움직임 감지. 평평하게 놓고 리셋 |
| `ERR,CALIBRATION_READ_FAILED`, `I2C_READ_FAILED` | 측정 통신 실패. 해당 기록으로 판정하지 않고 접촉 확인 후 재측정 |
| `ERR,SAMPLE_TIMING_FAILED` | 정상 출력 주기를 놓침. 해당 기록으로 판정하지 않고 원인 확인 후 재시작 |

오류 뒤에는 재시작 전까지 WME 샘플을 내보내지 않는다. 오류를 무시해도 계속 움직이는 화면 동작은 FRONT와 협의할 문제다.

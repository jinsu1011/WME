## 1. 서비스 개요

### 1.1 서비스 이름

**WME (We Make Experts)** — 장비를 운용하는 기업을 위한 B2B 사내 기술교육 플랫폼

### 1.2 한 줄 정의

신입 기술자가 **실장비에 투입되기 전에**, 장비 조작의 원리와 "무엇을 먼저 확인할지" 판단하는 연습을
웹에서 반복하고, 매니저는 그 **실습 기록과 성취도**를 확인하는 서비스.

### 1.3 배경 — 문제 정의

| 구분 | 내용 |
|---|---|
| 현황 | 신입·전환배치 기술자는 장비 원리를 설명으로 배운 뒤 곧바로 실장비 실습·현장에 투입된다 |
| 원인 | 실장비 실습은 **장비 점유·지도 인력·사고 위험**이 모두 비용이라, 원하는 만큼 반복할 수 없다 |
| 문제 1 (학습자) | 조작 순서와 판단을 **틀려 보고 다시 해 볼 기회**가 부족하다 |
| 문제 2 (매니저) | 실습이 기록으로 남지 않아 **누가 어디서 막히는지** 확인하기 어렵다. 결과(통과 여부)만 보고 과정(보정 경로·판단 이유)은 보지 못한다 |

> 수치(비용·시간 절감률 등)는 검증하지 않았으므로 쓰지 않는다.

### 1.4 포지셔닝

> **실장비 실습을 대체하는 것이 아니다. 실장비에 투입되기 전에, 원리를 익히고 판단을 연습하는 단계를 저비용으로 반복하게 한다.**

### 1.5 핵심 가치와 주요 기능

| 핵심 가치 | 해결하는 문제 | 주요 기능 |
|---|---|---|
| **반복 가능한 실습** | 문제 1 | 정렬 실습(3D 장비 뷰), 판단 실습, 재실습(이전 기록 보존) |
| **과정이 남는 기록** | 문제 2 | 조작 궤적·보정 구간 자동 분석, 조정 순서·이유 제출 |
| **기준에 따른 피드백** | 문제 1 | 루브릭 4기준 규칙 기반 채점, AI 학습 피드백(근거 구간 제시) |
| **매니저 가시성** | 문제 2 | 반 전체 현황, 학습자별 진도·성취도·기록 드릴다운 |

### 1.6 데모 설정

반도체 장비 기업(가상 고객사)에 납품한 인스턴스로 시연한다. 대표 과정은
**「포토공정 입문 — 마스크·웨이퍼 정렬 실습」**(조작형)과 **「노광 불량 상황 판단」**(판단형) 2개.
제품 코드는 업종 중립이고, 업종 내용은 과정 데이터에만 있다.

### 1.7 범위

| 포함 | 제외 (범위 밖) |
|---|---|
| 로그인([설계]) · 역할별 화면 | 회원가입 · 비밀번호 찾기 · 권한 관리 |
| 과정 카탈로그 · 배정된 실습 목록 · 대기방 | 과정 작성·편집 · 학습자 배정 화면 (시드 데이터로 제공) |
| 정렬 실습 (키보드 기본 / 교육용 모형 컨트롤러 선택) · 판단 실습 | 실장비 연동 · 정비 기술 교육 |
| 결과 · 규칙 기반 채점 · AI 피드백 · 재실습 | 수료증 · 결제 · 알림 |
| 매니저 현황 · 학습자별 성취도 | 배포(호스팅) · 다중 고객사 운영 |

## 5. 고려사항 (설계상 고민 · 다음 단계)

1. **센서는 서버를 거치지 않는다(Web Serial).** 조작은 즉시 반응해야 해서 브라우저가 USB 로 직접 읽고 좌표로 변환한다. 그래서 센서 전용 API 가 없고, 결과 좌표만 WebSocket 으로 기록한다. 크롬 계열에서만 동작한다
2. **실시간 기록은 WebSocket**(초당 약 25회). OpenAPI 로 표현하지 않으므로 API 명세 description 에 메시지 구조를 적었다
3. **판정은 서버가 한다.** 허용 범위 통과 여부·분석·채점은 화면이 보낸 값을 믿지 않고 서버가 과정 설정값으로 계산한다
4. **채점 출처를 구분한다.** 규칙 기반 채점(`rule`)과 LLM 채점(`llm`)을 필드로 구분하고 화면에 표시한다. 규칙 채점을 AI 채점이라고 부르지 않는다
5. **AI 가 실패해도 교육은 멈추지 않는다.** 답변 저장 → 규칙 채점 → AI 피드백 순서라 LLM 이 없어도 기록·성취도가 채워진다
6. **업종 중립 구조.** 과정 내용·허용 오차·조작 계수·채점 규칙이 과정 데이터(`content_json`)에 있어, 다른 업종은 데이터만 바꾼다
7. **논리 설계와 시연 앱 저장 방식.** 데이터 모델(ERD)은 화면·API 가 쓰는 모든 데이터를 테이블로 정규화한 논리 설계다(단계·루브릭·기준별 점수·판단 순서·피드백 문장·근거 구간 등). 시연 앱은 3일 일정에 맞춰 같은 데이터를 6개 테이블 + JSON 컬럼으로 저장하고, API 는 논리 설계와 같은 구조로 내려준다. 과정 편집·통계 질의가 필요해지는 다음 단계에서 논리 설계대로 분리한다
8. **인증.** 시연 앱은 데모 로그인(역할 전환)이며 인증 구현이 아니다. 설계에는 로그인 API·비밀번호 해시를 넣었다. 다음 단계에서 세션/토큰 인증과 역할별 접근 제어를 구현한다
9. **허용 오차는 교육 과정 설정값**이며 실제 장비의 정렬 정밀도가 아니다. 모형은 교육용이다
10. **센서 모드의 한계.** 모형 센서(MPU6050)는 기울기·회전만 잴 수 있고 위치는 잴 수 없다. 그래서 센서 모드는 위치를 가운데 고정하고 평행·회전 연습에 쓴다. 이 모드의 기록은 위치 정확도가 자동으로 충족되므로, 시도마다 저장되는 입력 장치(`input_device`)로 구분해서 본다. 수평 허용 범위·유지 시간·축 방향은 모형마다 다른 화면 보정값이라 지금은 화면에 두었고, 여러 모형을 운영할 때 과정 설정으로 옮긴다

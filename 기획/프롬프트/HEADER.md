## 오늘 할 일 — 이 순서로

### 1. 수업 확인 사항 정리 (내가 수업에서 들은 걸 알려주면 반영)
- 파일명에 "판교캠퍼스" 포함 여부 → `제출/체크리스트.md` A 표
- 발표 때 무엇을 띄우는지 (개요 PDF / 별도 슬라이드)
- 1일차 가이드(서비스 개요·요구사항·UI 흐름도)에서 **새로 요구한 형식**이 있으면 `과제요건.md` 에 추가하고 서비스개요·화면설계에 반영
- LLM 키 수령 여부

### 2. 제출 파일을 실제 도구로 열어 확인 (BACK·FRONT 를 기다리는 동안)
- `제출/WME-API.yml` → **Swagger Editor** (https://editor-next.swagger.io) 에 붙여 넣고 오류·경고 0 확인, 화면 캡처(PDF 용)
- `제출/WME-DB.dbml` → **dbdiagram.io** 에 붙여 넣고 ERD 가 오류 없이 그려지는지, 그룹 4개가 보이게 배치해 캡처
- 브라우저 도구를 쓸 수 있으면 직접 한다. 사이트에 로그인·가입이 필요하면 멈추고 나에게 맡긴다
- 캡처는 `제출/도구캡처/` 에 저장 (ERD·Swagger)

### 3. BACK·FRONT 결과로 보정
- `기획/작업로그/Back.md` 대조표를 읽고 **YAML·DBML 을 고친다** (서버 쪽을 고쳐야 하면 BACK 에 넘길 지시문을 써 준다)
- `기획/작업로그/Front.md` 에서 M1·M2 결과, 캡처 중 발견한 "화면설계와 실제 화면 차이" → `화면설계.md` 보정
- 보정 후 `화면설계.md` 4절 **UI↔API↔DB 대조표**가 셋 다 맞는지 다시 확인. 다른 세션 보고를 그대로 믿지 말고 실제 파일·서버 GET 응답으로 대조

### 4. 개요 PDF 조립 — 캡처 24장이 오면
- 목차(과제 PDF 4쪽 순서 그대로): 서비스 개요 → 시스템 액터 정의 → **UI 흐름도(캡처)** → 데이터 모델(ERD 캡처) → API 명세(Swagger 캡처 + API 목록 표) → 고려사항
- UI 흐름도: 캡처마다 **강조 박스·번호·화살표 + 버튼/입력/데이터 설명**, 액터별(신입사원·매니저)로 묶고 예외 화면(C-02·C-12·C-19) 포함
- 과제 PDF 예시(회의실 예약 서비스)의 쪽 구성·밀도를 따른다
- 만드는 방법은 먼저 나에게 제안하고 고르게 해줘 (예: HTML → PDF 인쇄 / PPT → PDF). 결과 파일: `제출/9반_김진수_WME-개요.pdf`
- `[설계]` 표기(로그인 API 등)와 "허용 오차는 교육 과정 설정값" 고지를 유지

## 지켜야 할 규칙
- **구현하지 않은 것을 구현했다고 쓰지 않는다.** 설계만 한 것은 `[설계]`
- 검증하지 않은 수치(정확도 %, 절감률 등)를 쓰지 않는다
- **"실장비 대체"라고 쓰지 않는다.** 투입 전 판단 훈련이다
- 규칙 기반 채점을 AI 채점이라고 부르지 않는다. LLM 이 실제로 성공한 경우에만 AI 피드백이라고 쓴다
- 모형은 교육용 컨트롤러라고 명시한다
- 제출물의 필드·코드는 실제 서버와 대조한 것만 쓴다
- git commit/push 는 내가 요청할 때만 한다
